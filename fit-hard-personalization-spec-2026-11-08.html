01. Product vision and architecture

The central concept

Fit Hard must operate as one connected system, not a collection of independent features.

The user's profile is the source of truth. The meal engine, workout engine, calendar, progression system, mascot and notifications all read from the same profile and update from the same underlying records.

PERSONAL PROFILE

Goals, body data, preferences, equipment, availability.

MEAL ENGINE

Calories, protein, recipes, ingredients and shopping.

TRAINING ENGINE

Muscle groups, splits, exercises and recovery.

PROGRESSION

Performance, weights, repetitions and adjustments.

CALENDAR

Meals, training, rest, appointments and tracking.

MASCOT

Recommendations, feedback and motivation.

Critical architecture rule

Never calculate different calorie targets independently in different screens. Never create a workout that ignores the user's equipment. Never generate a shopping list independently of the selected recipes.

All features must use shared services.

NutritionServiceCalculates energy, macros and meal targets.

Implementation requirement: The app must work without an internet connection for core functions. Store the recipe database, exercise database, routines, profile, progress and calendar locally. Use optional synchronization if the existing app supports it.

Character appearance field

The characterAppearance field stores the appearance selected by the user during account setup.

Supported values:

  • boy
  • girl
  • nonBinary

This is a visual customization preference. It must not be used to infer the user's gender identity, biological characteristics or medical requirements.

Character persistence and consistency

  • Save the selection to the user's persistent profile.
  • Display the selected character as the user's app icon or avatar.
  • Use the matching character appearance in exercise animations.
  • Keep the same selected appearance across the app.
  • Restore the selection after logout and login.
  • Preserve the selection when updating the app.
  • Allow the user to change their appearance later in Profile Settings.
  • Changing appearance must not delete workout history, routines or progress.
  • Support the non-binary appearance as a complete, intentional visual option, not as an incomplete fallback.

The app must use a consistent character asset family for all three appearance options. The same exercise movement, machine interaction, camera angle and animation timing must be maintained across variants.

Profile update behavior

  • Changing a goal triggers a recalculation of relevant targets.
  • Changing weight triggers updated nutrition estimates when appropriate.
  • Changing equipment triggers workout exercise substitution.
  • Changing training availability triggers schedule regeneration suggestions.
  • Changing dietary preferences filters future recipes.
  • Changing allergies immediately removes unsafe recipes and substitutions.
  • Changing character appearance updates the app avatar and matching exercise animation assets.
  • Changing a meal does not unnecessarily change other meals.

Existing completed workouts and historical meal records must never be silently rewritten when a profile changes.

Nutrition calculation

Estimate resting energy expenditure using a validated method, such as Mifflin-St Jeor, when its assumptions are appropriate. Estimate daily energy expenditure using activity information. Use observed weight trends to calibrate estimates over time.

The calorie target must depend on the user's goal, age, activity, weight, training and safety flags.

Do not impose aggressive deficits or guarantee a specific rate of weight loss.

For eligible exercising adults, a configurable protein starting reference can use 1.4–2.0 g/kg/day, adjusted for context and professional advice.

Calculate fats and carbohydrates from the remaining energy budget using a validated configurable nutrition policy. Never create macronutrient totals that exceed or contradict the calorie target without explaining rounding differences.

Exercise animation quality standard

Every exercise and machine must have a professionally checked demonstration animation. An animation is not acceptable merely because it shows a character near a machine. The character must visibly and correctly perform the exercise using the actual equipment.

NON NEGOTIABLE QUALITY REQUIREMENT A character that appears to float beside a machine, pass through equipment, use the wrong machine parts or perform a movement that does not physically connect to the machine is a FAILED animation. It must not be published in the app.

Every animation must meet all of these requirements:

  1. Realistic body movement: The character must have believable human proportions, joint movement and body positioning.
  2. Correct machine interaction: Hands, feet, back and other contact points must remain correctly positioned against the relevant machine surfaces.
  3. Correct exercise form: The animation must demonstrate the intended movement, range of motion and body alignment.
  4. No overlapping parts: The character must not intersect, pass through or visibly overlap machine components or their own body in an anatomically incorrect way.
  5. No broken frames: There must be no distorted limbs, missing body parts, flickering, sudden position jumps or visual glitches.
  6. Smooth movement: The movement must have consistent timing and believable transitions.
  7. Seamless loop: The animation must return to its initial position smoothly without a visible jump or sudden reset.
  8. Correct camera angle: The user must be able to understand how the machine and body interact.
  9. Visible movement: The relevant working muscles and movement should be easy to understand from the demonstration.
  10. Character consistency: The character must match the appearance selected in the user's profile.

Animation production and approval

Use professionally produced, properly licensed 3D or 2D exercise assets. Prefer 3D assets where realistic machine contact and body movement require multiple viewing angles.

Animations may be created using rigged character models and equipment models. They must be reviewed by a qualified exercise professional or appropriately knowledgeable reviewer for movement accuracy.

Create one approved master animation for each exercise movement. Generate or produce matching character appearance variants without changing the underlying movement or machine mechanics.

Do not generate different unverified animations randomly for different users.

Each exercise animation must pass visual quality assurance before being marked approved and available in training mode.

Training volume rules

The engine should count both direct and indirect muscle work. For example, pressing exercises also involve triceps and shoulders. Do not count every compound set as a full direct set for every involved muscle.

For healthy adults seeking hypertrophy, approximately 10 weekly sets per muscle group is a useful evidence-based reference, not a compulsory starting target. Beginners may need less. Advanced users may tolerate different volumes.

Start conservatively and increase volume only when the user is recovering and progressing.

Routine duration

Create an initial four-week training block. Repeat effective exercises across sessions to make performance measurable. The user can continue a successful program beyond four weeks.

At the end of the block, evaluate:

  • Strength changes.
  • Completed sets and repetitions.
  • Recovery.
  • Training consistency.
  • Difficulty ratings.
  • Goal changes.

Generate a new block or maintain the existing program based on actual performance. Never automatically replace all exercises just because a calendar period has ended.

Routine generation result

Once generated, save every session to the Routines library and schedule it on the calendar.

06. Progressive overload engine

This is a core Fit Hard differentiator. The app should remember every exercise and help users make measurable progress instead of giving them the same static routine indefinitely.

Information to track per exercise

  • Weight used.
  • Completed repetitions.
  • Prescribed sets.
  • Completed sets.
  • Rest time.
  • Difficulty rating or RIR.
  • Exercise technique feedback.
  • Historical performance.

Double progression

Use repetition ranges and resistance increases as the primary progression method for appropriate exercises.

Example:

SessionWeightRepetitions
130 kg8, 8, 8
230 kg9, 8, 8
330 kg10, 10, 9
430 kg12, 12, 12
532.5 kg8, 8, 8

These are illustrative targets. A progression recommendation must also account for technique and perceived effort.

Progression rules

  1. Establish an appropriate starting weight or bodyweight variation.
  2. Set an exercise-specific repetition range.
  3. Track every completed set.
  4. When the user reaches the upper end of the range across all prescribed sets with good technique, assess whether a small resistance increase is appropriate.
  5. Recommend an achievable increase based on available equipment.
  6. After increasing weight, reduce the repetition target within the range if necessary.
  7. Record the new performance baseline.

When not to increase difficulty

  • Technique is deteriorating.
  • The user reports excessive fatigue.
  • Performance has repeatedly declined.
  • The user reports pain or injury.
  • The user has not completed the prescribed work.

Do not interpret pain as a normal training challenge. Stop the affected exercise and recommend appropriate professional advice.

Deload and recovery logic

A deload should be suggested when accumulated fatigue, performance decline and recovery feedback indicate that a reduction may help. It should not be forced automatically every fourth week.

Possible adjustments include reducing sets, reducing load, increasing rest or temporarily replacing a demanding exercise.

Progress display

Show:

  • Personal records.
  • Weight progression graphs.
  • Repetition progression graphs.
  • Training consistency.
  • Weekly completed volume.
  • Muscle group training history.

Mascot help writing rules

This is a strict content requirement. The mascot's exercise instructions must follow every rule below:

  1. Use very simple everyday words.
  2. Write as if a friendly person is helping someone at the gym.
  3. Use very short steps.
  4. Include only the information the user needs to perform the movement.
  5. Use a small amount of text.
  6. Make each step easy for a complete beginner to understand.
  7. Explain machine setup and body positioning where relevant.
  8. Explain the movement in a clear order.
  9. Use numbered steps rather than long paragraphs.
  10. Never use dash characters of any kind anywhere in the help text.
  11. Never use hyphenated words.
  12. Never use bullet characters.
  13. Never use complicated anatomy or technical language when a simpler word works.
  14. Never use unnecessary motivational speeches.
  15. Keep the tone friendly, reassuring and human.

The no dash rule applies to every character in the displayed help content, including titles, instructions and closing messages. Use numbered steps with ordinary punctuation only.

Complete mascot help example 1: Leg press

MAScot HELP: LEG PRESS

Let's do it together!

1. Sit back and rest your head.

2. Put your feet on the platform.

3. Keep your feet about shoulder width apart.

4. Slowly bend your knees and lower the platform.

5. Push the platform away without locking your knees.

6. Repeat slowly and stay in control.

You've got this!

Complete mascot help example 2: Lat pulldown

MASCOT HELP: LAT PULLDOWN

I'll show you how!

1. Sit down and place your thighs under the pads.

2. Hold the bar with both hands.

3. Sit tall and keep your chest up.

4. Pull the bar down towards your upper chest.

5. Slowly let the bar go back up.

6. Repeat without swinging your body.

Nice and steady!

These examples are the exact writing standard to follow. Each exercise needs its own accurate instructions. Do not reuse the leg press instructions for another machine.

10. Medication and peptide tracking

Important medical and regulatory boundary: Fit Hard must not prescribe peptides, recommend experimental compounds, calculate injectable doses or supply default dosing protocols. In Australia, many peptides promoted for fitness, recovery and weight loss are unapproved therapeutic goods. The TGA warns about significant risks, including incorrect ingredients, unreliable labelling and serious adverse effects.

This feature should function as a private medication and prescribed-treatment tracking tool.

Medication section

Allow users to:

  • Add a prescribed medication or peptide by name.
  • Enter the product exactly as prescribed.
  • Record prescribed dosage and units.
  • Record route of administration as directed.
  • Record prescribed frequency.
  • Enter clinician-provided instructions.
  • Set reminder dates and times.
  • Record the prescribing professional if desired.
  • Pause or discontinue tracking.

Dosage entry

Support clinician-prescribed custom entries and unit selection. Do not offer generic recommended doses or prefilled injectable dosage protocols.

If the user changes their dosage, clearly explain that they must follow their prescriber's instructions.

Medication reminder interface

MY MEDICATION SCHEDULE

Prescribed amount: User-entered amount and unit

Time: User-selected time

Frequency: User-entered prescribed schedule

Safety requirements

  • Never suggest changing a dose.
  • Never calculate injection preparation or reconstitution.
  • Never infer a dose from body weight.
  • Never recommend combining peptides.
  • Do not promote unapproved products as safe or effective.
  • Allow the user to record prescribed medicines without providing medical advice.
  • Provide links to official medicine information where possible.

Only populate an approved medicine catalogue using verified, current regulatory data. Do not represent an unapproved experimental peptide list as an approved treatment catalogue.

Exercise animation visual quality

Exercise animations are a core instructional part of Fit Hard. They must be treated as production assets, not decorative illustrations.

  • Characters must look like real people performing the actual exercise.

  • No body part may visibly pass through or incorrectly overlap equipment.

  • Movement must be smooth and natural.
  • Loops must be seamless.
  • Animations must match the selected character appearance.

Every exercise screen must contain a round question mark button. It must be easy to find, consistently positioned and large enough to tap comfortably.
